## 왜 이 주제인가 (팀이 씁니다)

저희 팀은 경찰 과학수사에서 증거를 분석하는 방법에 관심이 있어 이 주제를 선정했습니다. 범죄 현장에서는 옷이나 천에서 떨어진 작은 섬유가 증거로 발견될 수 있습니다. 섬유마다 화학적 성질이 다르기 때문에 적외선 스펙트럼을 분석하면 섬유의 종류를 구분하는 데 도움이 될 수 있습니다. 그래서 실제 섬유 스펙트럼 데이터를 이용해 컴퓨터가 섬유의 종류를 얼마나 잘 구분하는지 확인하고 싶었습니다. 화학에서 배우는 물질의 성질과 경찰 과학수사를 데이터 분석으로 연결할 수 있다는 점에서 의미가 있다고 생각했습니다.

## 데이터

- 출처: *A dataset of infrared (ATR-FTIR) spectra for textile fibres of natural and man-made origin*. Mendeley Data에 공개된 섬유의 적외선 스펙트럼 데이터입니다.
- 데이터 주소: https://data.mendeley.com/datasets/rx3fjgz96x/3
- DOI: https://doi.org/10.17632/rx3fjgz96x.3
- 라이선스: CC BY 4.0. 데이터를 이용할 때 원 출처와 저작자 정보를 표시해야 합니다.
- 기간·행 수·열 수: 공개된 데이터 설명에 따르면 섬유 시료 137개에서 얻은 스펙트럼 160개를 포함합니다. 실제 분석 파일은 160행이며, 정확한 열 수는 코드로 확인합니다.
- 사용한 열: 입력은 파수에 따른 스펙트럼 측정값이며, 예측할 값은 `Subtype`(세부 섬유 종류)입니다. `Sample_ID`는 같은 시료의 측정값이 학습 데이터와 시험 데이터에 동시에 포함되지 않도록 데이터를 나눌 때 활용합니다.
- 개인정보 확인: 데이터는 섬유 시료와 스펙트럼 측정값을 중심으로 구성되어 있습니다. 분석 전에 이름, 연락처, 주소 등 개인을 식별할 수 있는 정보가 포함되어 있지 않은지 확인합니다.

### 데이터에서 찾은 구멍과 전처리 판단

- `Subtype`의 종류별 데이터 수를 확인합니다. 특정 섬유 종류의 데이터가 너무 적으면 모델이 그 종류를 제대로 학습하지 못할 수 있습니다.
- 결측값이나 숫자가 아닌 값이 있는지 확인합니다. 결측값이 있다면 원인을 확인한 뒤 처리하고, 이유 없이 평균값으로 채우지 않습니다.
- `Spectrum_ID`, `Sample_ID`, `Replica`, `Type`, `Origin`은 기본적인 입력 변수에서 제외합니다. 특히 `Sample_ID`는 같은 시료에서 반복 측정한 데이터가 학습용과 시험용에 동시에 들어가는지 확인하는 데 사용합니다.
- 같은 시료에서 나온 스펙트럼이 학습 데이터와 시험 데이터에 동시에 포함되면 모델의 성능이 실제보다 높게 나올 수 있습니다. 따라서 가능하면 `Sample_ID`를 기준으로 데이터를 나눕니다.
- 공개된 데이터 설명에는 세부 섬유 종류가 26개로 소개되어 있지만, 현재 분석 파일에서는 `Subtype`의 서로 다른 값이 31개로 확인되었습니다. 데이터 설명과 실제 파일의 차이를 확인하고, 최종 분석에는 실제 사용한 파일의 구성을 기준으로 기록합니다.

## 방법

분류 분석을 사용합니다. 스펙트럼 측정값을 입력하면 `Subtype`에 기록된 섬유 종류를 예측하도록 모델을 학습합니다. 예측한 결과를 실제 섬유 종류와 비교해 컴퓨터가 섬유를 얼마나 정확하게 구분하는지 확인합니다.

### 분석 과정

1. 데이터 수집: Mendeley Data에서 공개한 섬유 적외선 스펙트럼 데이터 중 `05_feature_matrix_preprocessed_als_snv_sgd2.csv` 파일을 사용합니다.
2. 변수 선택: 입력은 파수에 따른 스펙트럼 측정값, 예측할 값은 `Subtype`으로 정합니다.
3. 전처리: 데이터의 결측값과 중복값을 확인하고, 분류에 직접 사용하지 않는 식별 열을 입력 변수에서 제외합니다.
4. 분할: 학습용 데이터와 시험용 데이터를 나눕니다. 같은 `Sample_ID`의 측정값이 두 데이터에 동시에 들어가지 않도록 합니다.
5. 기준선: 모든 데이터를 가장 많이 등장하는 섬유 종류로 예측하는 단순 모델을 만들어 비교 기준으로 사용합니다.
6. 후보 모델 비교: k-NN 분류, 결정 트리 분류, 랜덤 포레스트 분류를 같은 데이터 분할에서 비교합니다.
7. 선택: 시험 데이터의 평가 결과와 모델의 설명 가능성을 고려해 최종 모델을 정합니다.
8. 평가: 정확도와 혼동 행렬을 확인합니다. 종류별 데이터 수가 다르면 macro F1-score와 balanced accuracy도 함께 확인합니다.
9. 해석: 어떤 섬유 종류를 잘 구분하고 어떤 종류를 자주 헷갈리는지 확인합니다.
10. 한계 점검: 데이터 수가 많지 않고 같은 시료에서 반복 측정한 값이 있다는 점, 실제 범죄 현장의 섬유와 실험실 데이터가 다를 수 있다는 점을 고려합니다.

### 후보 모델 비교

실제 모델을 실행한 뒤 같은 데이터 분할에서 결과를 비교합니다. 아직 계산하지 않은 성능 수치는 임의로 작성하지 않습니다.

| 후보 모델 | 정확도 | Macro F1-score | 특징 |
|---|---|---|---|
| 최빈 클래스 기준 모델 | 분석 후 작성 | 분석 후 작성 | 가장 많이 등장하는 종류만 예측 |
| k-NN 분류 | 분석 후 작성 | 분석 후 작성 | 스펙트럼이 비슷한 데이터의 종류를 참고 |
| 결정 트리 분류 | 분석 후 작성 | 분석 후 작성 | 측정값을 기준으로 단계적으로 분류 |
| 랜덤 포레스트 분류 | 분석 후 작성 | 분석 후 작성 | 여러 결정 트리의 예측 결과를 모아 분류 |

### 왜 이 모델을 선택했는가

실제 분석 결과를 확인한 뒤 최종 모델을 선택합니다. 정확도가 가장 높은 모델만 고르기보다는 기준 모델보다 성능이 좋아졌는지, 특정 섬유 종류만 잘 맞히는 것은 아닌지, 결과를 설명하기 쉬운지도 함께 고려합니다.

### 모델링 과정에서 우리 팀이 결정한 것

- 스펙트럼 측정값을 입력 변수로 사용하고 `Subtype`을 예측 대상으로 정했습니다.
- `Sample_ID`는 예측 입력으로 사용하지 않고 데이터 분할 과정에서 활용합니다.
- 같은 시료의 측정값이 학습용과 시험용에 동시에 포함되지 않도록 주의합니다.
- 정확도뿐만 아니라 섬유 종류별 분류 성능도 확인합니다.

## 결과 해석 (팀이 씁니다)

- 사용한 지표와 수치: 정확도는 전체 시험 데이터 중 종류를 맞힌 비율입니다. Macro F1-score는 각 섬유 종류의 분류 성능을 고려한 지표이며, 혼동 행렬은 실제 종류와 예측한 종류가 어떻게 다른지 보여 줍니다. 실제 분석 후 계산한 수치를 기록합니다.
- 기준선과 비교하면: 가장 많이 등장하는 섬유 종류만 예측하는 기준 모델과 비교해 스펙트럼을 사용한 모델의 성능이 얼마나 좋아졌는지 확인합니다.
- 이 결과가 뜻하는 것: 스펙트럼을 이용해 섬유 종류를 어느 정도 구분할 수 있는지, 어떤 종류끼리 구분하기 어려운지 결과를 바탕으로 해석합니다.

### 우리 팀이 찾아낸 것

1. **스펙트럼으로 섬유 종류를 얼마나 구분할 수 있는가?**
   - 근거: 실제 분석에서 나온 정확도와 macro F1-score를 기록합니다.
   - 뜻: 스펙트럼 측정값이 섬유 종류를 구분하는 데 얼마나 도움이 되는지 해석합니다.

2. **어떤 섬유 종류를 서로 헷갈리는가?**
   - 근거: 혼동 행렬에서 오분류가 자주 발생한 종류를 확인합니다.
   - 뜻: 화학적 특징이 비슷하거나 데이터가 부족한 섬유 종류가 있는지 살펴봅니다.

3. **어떤 모델이 가장 적합한가?**
   - 근거: 같은 시험 데이터에서 각 모델의 정확도와 macro F1-score를 비교합니다.
   - 뜻: 단순히 정확도가 높은 모델뿐 아니라 종류별 성능과 설명 가능성도 고려해 결론을 내립니다.

- 해석을 다시 확인한 것:
  1. 같은 시료의 측정값이 학습 데이터와 시험 데이터에 동시에 들어가지 않았는지 확인합니다.
  2. 정확도만 높고 일부 섬유 종류를 제대로 구분하지 못하는 것은 아닌지 확인합니다.
  3. 시험 데이터에서 나온 결과가 모든 종류의 섬유나 실제 범죄 현장에서도 똑같이 적용된다고 단정하지 않습니다.

`streamlit run app.py`

필요한 라이브러리는 `requirements.txt`에 기록합니다. 실제 파일 이름과 실행 환경에 맞게 명령어를 수정합니다.
